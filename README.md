# homebrew-tap

Homebrew formulae for my own tools.

```bash
brew install sapn95/tap/git-tidy
```

| Formula                                           | What it is                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| [bib](https://github.com/sapn95/browser-in-a-box) | Real, unmanaged browser in a box: a Linux container or a macOS VM       |
| [git-tidy](https://github.com/sapn95/git-tidy)    | Keep a directory full of git checkouts clean: sync, prune, clean, sweep |
| [pfadi](https://github.com/sapn95/pfadi)          | macOS file browser with an address bar you can click into and type      |

Each formula is generated by its own project's release workflow, so the version
and checksums here always match a published release.

## Why `main` takes direct pushes

`main` here has **no branch protection beyond a ruleset refusing deletion and
force-push**, and that is deliberate rather than an oversight. Please read this
before switching it back on.

The hourly updater in
[`update-formulae.yml`](.github/workflows/update-formulae.yml) commits straight
to `main` with the Actions token. It cannot go through a pull request instead,
and the reason is GitHub's own loop prevention:

- A pull request created with the Actions token **triggers no workflows**, so
  the required status checks never report and the pull request can never be
  merged. Eleven of them piled up unmerged before this was understood.
- The token is not an administrator, so it cannot bypass them.
- A bypass actor for the GitHub Actions app is the documented answer and is
  **org-only**. On a personal repository the API refuses it: *"Actor GitHub
  Actions integration must be part of the ruleset source or owner
  organization."*

What protection bought was review, and nobody reviews a machine-written
checksum. What it cost was every release needing somebody to press a button,
and the updater going red for having done its job.

Two things stand in its place:

- **`ruby -c` over every formula runs inside the update job, before the push.**
  It has to be there: a push made with the Actions token triggers no workflows
  either, so `ci.yml` cannot be the gate on what that job writes, however
  `main` is protected.
- **The ruleset still refuses deletion and force-push**, which binds the
  updater exactly as much as it binds anybody.

Turning classic protection back on does not break anything visibly — it stops
the updater, quietly, and the tap falls behind until somebody notices that
`brew upgrade` has not moved in a while.
